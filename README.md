# SNMPSIM Tools

This repository contains scripts that can be used to interact with snmpsim simulations

SNMPSIM is open source command line tool (running on Python) that can be used to simulate SNMP agents. Detailed information about how to use this tool can be found in the [official site](https://docs.lextudio.com/snmpsim/).

| Tool | Purpose |
|---|---|
| [qa_device_simulator_to_snmpsim.py](scripts/qa_device_simulator_to_snmpsim.py) | Convert a QA Device Simulator simulation (XML) to a snmprec file |
| [snmpwalk_to_snmpsim.py](scripts/snmpwalk_to_snmpsim.py) | Clean up a SNMP walk taken with Net-SNMP tools and convert it to a cleaned SNMP walk or a snmprec file |
| [snmpsimExecuteSingleSimulation.sh](scripts/snmpsimExecuteSingleSimulation.sh) | Run a single simulated SNMP agent |
| [snmpsimBulkv2.sh / snmpsimBulkv3.sh](scripts/snmpsimBulk) | Run simulated SNMP agents for a list of IP addresses (SNMPv2c / SNMPv3) |
| [snmpwalk](snmpwalk/README.md) | C# console application that takes SNMP walks (SNMPv1/v2c/v3), also directly as a snmprec file |

## Requirements

- Python 3.10 or later
- The Python packages listed in [requirements.txt](requirements.txt). They are needed to run simulations and to write snmprec files with `snmpwalk_to_snmpsim.py`. The QA Device Simulator conversion and the cleaned SNMP walk output have no dependencies

It is recommended to install the necessary libraries in a virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

>[!NOTE]
> On Ubuntu/Debian, the `venv` module is installed with `sudo apt install python3-venv`

## QA Device Simulator to SNMPSIM

### About

This script converts a simulator took from the QA Device Simulator (XML file) to a simulation that can be parsed by snmpsim (snmprec file). A snmprec file is a plain text that is used by snmpsim to simulate an SNMP agent.

### How to use

For example, if you would like to convert the simulation **qaDeviceSimulation.xml** to the file **convertedSimulation.snmprec**, please proceed as follows:

```bash

qa_device_simulator_to_snmpsim.py --input="C:\MyDirectory\qaDeviceSimulation.xml" --output="C:\MyDirectory\convertedSimulation.snmprec"
```

The generated file (in this case, **convertedSimulation.snmprec**) does not need be created before the script is executed. The script will create the file in case it does not exist. If the file already exists, it will be overwritten

The script exits with code 0 when the file was generated and with code 1 when the simulation could not be converted (e.g. the file does not exist or is not a valid XML file).

### Additional notes

- Some XML files generated by the QA Device Simulator contains invalid characters. For example:

```xml
<Definition OID="1.3.6.1.2.1.2.2.1.6.501" Type="OctetString" ReturnValue="&#x0;&#x0;&#x0;&#x0;&#x0;&#x14;" LogOutput="{INS}OID{INS} - {INS}ReturnValue{INS} ({INS}Type{INS})" Comment="" Delay="false" Save="false" SkipOID="false" />
```

In this case *&#x0* represents char(0) which is not valid in an XML document. This could be a consequence of a decoding issue (the QA Device simulator is decoding incorrectly a value retrieved by the device)
To surpass this constraint, the script reads these characters as the original bytes (no temporary file is created). Valid characters, such as line breaks (*&#xA;*), are kept as they are.

- Values that cannot be written as plain text (control characters such as the bytes of a MAC address, line breaks, non-ASCII characters or trailing spaces) are written in hexadecimal. For example, the definition above is converted to:

```text
1.3.6.1.2.1.2.2.1.6.501|4x|000000000014
```

- The records are sorted by OID, which is required by snmpsim to answer GETNEXT/GETBULK requests (e.g. SNMP walks). When an OID is defined more than once, only the first definition is kept
- Definitions with an unsupported type or with an invalid value for their type (e.g. a Counter32 that is not a number) are skipped. The script lists them when it finishes

## SNMP walk to SNMPSIM

### About

This script cleans up a SNMP walk (took by Net-SNMP tools) so it can be used by snmpsim. The result can be written as:

- A cleaned SNMP walk (default). snmpsim can use it directly when the file has the extension *.snmpwalk*
- A snmprec file, when the output file has the extension *.snmprec* (or `--format snmprec` is used). This requires the packages of [requirements.txt](requirements.txt). The records are sorted by OID and duplicated records are removed

The following issues are fixed:

- Encoding: files saved as UTF-16 (e.g. with a PowerShell redirection), UTF-8 (with or without byte order mark) or Latin-1 are supported
- Values spanning several lines (e.g. a sysDescr with line breaks or a long Hex-STRING) are joined into one record
- STRING values with line breaks, control characters or non-ASCII characters are written as Hex-STRING, so snmpsim returns the same bytes as the device
- INTEGER/Gauge32 values formatted with a DISPLAY-HINT (e.g. *INTEGER: 5.3 TenthdBmV*) are converted to the raw value (*INTEGER: 53*)
- Records without a value (*No Such Object*, *No Such Instance*, *No more variables left in this MIB View*) and lines that are not part of a record (e.g. *End of MIB*) are removed
- Non-printable characters are removed from the other records

### How to use

Take the SNMP walk with numeric OIDs (`-On`), for example:

```bash
snmpwalk -v2c -c public -On 10.11.12.13 .1.3.6.1 > myDevice.walk
```

Then convert it:

```bash
# Cleaned SNMP walk
python3 snmpwalk_to_snmpsim.py --input myDevice.walk --output myDevice.snmpwalk

# snmprec file
python3 snmpwalk_to_snmpsim.py --input myDevice.walk --output myDevice.snmprec
```

The script lists the records that were changed or removed. It exits with code 0 when the file was generated and with code 1 otherwise.

## SNMPSIM Execute Single Simulation

The purpose of this bash script is to reduce the number of argument that are required to execute SNMPSIM to simulate a single SNMP agent.

### Arguments

- f|snmprecFolder: The folder that contains the simulation file (full path)
- i|ipAddress: The IP address of the simulated SNMP agent
- p|Port: The port of the simulated SNMP agent (range [1024, 65535])

Optional arguments:

- l|lite: Use `snmpsim-command-responder-lite` (SNMPv1/v2c only) instead of `snmpsim-command-responder`
- m|variationModulesFolder: Folder with snmpsim variation modules. By default, the variation modules installed with snmpsim are used

### How to use

```bash
snmpsimExecuteSingleSimulation.sh --snmprecFolder /home/myUser/mySnmprecFolder --ipAddress 10.11.12.13 --port 10161
snmpsimExecuteSingleSimulation.sh -f /home/myUser/mySnmprecFolder -i 10.11.12.13 -p 10161
```

The SNMP community is the name of the simulation file (e.g. *myDevice* for *myDevice.snmprec*).

Each simulation has its own PID file and log file, named after the simulation folder, the IP address and the port:

- PID file: `~/Documents/snmpsim/debug/daemon/<folder>_<ipAddress>_<port>.pid`
- Log file: `~/Documents/snmpsim/debug/logging/<folder>_<ipAddress>_<port>.txt`

To stop a simulation:

```bash
kill $(cat ~/Documents/snmpsim/debug/daemon/mySnmprecFolder_10.11.12.13_10161.pid)
```

>[!IMPORTANT]
> - `snmpsim-command-responder` is used by default. It supports SNMPv1/v2c/v3 and works with snmpsim 1.2.x and snmpsim-lextudio 1.1.x. `snmpsim-command-responder-lite` (option `--lite`) does not start with snmpsim 1.2.x
> - snmpsim is found in the activated virtual environment, in the PATH or in `~/.local/bin`
> - The script exits with code 0 when the simulation is running and with code 1 otherwise

## SNMPSIM Bulk

These bash scripts run one snmpsim instance for each IP address available in a file. `snmpsimBulkv2.sh` is used for SNMPv1/v2c simulations and `snmpsimBulkv3.sh` for SNMPv3 simulations.

### How to use

```bash
snmpsimBulkv2.sh [options] fileName initialTransportOffset
snmpsimBulkv3.sh [options] fileName initialTransportOffset
```

- fileName: File with one IP address (or IP address:port) per line. Empty lines and lines starting with # are ignored
- initialTransportOffset: Initial transport offset. For each IP address, the transport offset is incremented by one

| Option | Description | Default |
|---|---|---|
| `-d`, `--data-dir` | SNMP data directory | `/home/skyline/.local/snmpsim/data/public` |
| `-u`, `--process-user` | User used by snmpsim when the script is executed as root | `skyline` |
| `-g`, `--process-group` | Group used by snmpsim when the script is executed as root | `skyline` |
| `-L`, `--log-dir` | Folder with one log file per instance | `/tmp/snmpsimBulk` |
| `-c`, `--command` | Path of `snmpsim-command-responder` | Activated virtual environment, PATH or `/home/<process user>/.local/bin` |
| `-l`, `--lite` | (v2 only) Use `snmpsim-command-responder-lite` | |
| `--v3-user` | (v3 only) SNMPv3 user | `skyline` |
| `--v3-auth-key`, `--v3-auth-proto` | (v3 only) SNMPv3 authentication key and protocol | `Skyline321`, `MD5` |
| `--v3-priv-key`, `--v3-priv-proto` | (v3 only) SNMPv3 privacy key and protocol | `Skyline321`, `DES` |

For example, to simulate agents on the default SNMP port (161), the script has to be executed as root:

```bash
sudo ./snmpsimBulkv2.sh ipAddresses.txt 1
```

The script exits with code 0 when all the instances are running.
